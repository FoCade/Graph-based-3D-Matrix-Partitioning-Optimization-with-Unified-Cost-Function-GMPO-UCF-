## 项目简介

本项目实现了一种基于图模型与统一代价函数的三维矩阵分片优化方法与系统。针对张量处理单元（Tensor Processing Unit）等专用硬件加速器上的大规模矩阵乘法计算，本系统通过 **"场景识别—分流决策—图搜索优化—调度生成"** 的流水线架构，自动搜索并生成高性能的矩阵分片与调度方案。

与传统的固定尺寸策略或启发式规则策略相比，本方法能够在广阔的解空间中进行系统性搜索，摆脱"贪心"决策导致的局部最优困境，获得全局近似最优的分片方案。

## 背景与动机

以矩阵乘法为核心的张量计算是推荐检索、以图搜图、自然语言处理等语音与视觉智能任务的基础工作负载。为满足此类计算在云端与边缘侧的性能与能效需求，业界普遍采用专用硬件加速器（如张量处理单元等）。

此类加速器通常采用 **存算分离架构**，其片上高速本地内存的容量远小于片外大容量的全局内存。因此，在执行大规模矩阵乘法时，由于矩阵无法被一次性完整加载，必须采用 **分片技术**——将大矩阵切分为多个较小的数据块，并分批次从全局内存调度至本地内存进行计算。

现有技术中用于指导分片和调度的策略主要包括：

| 策略 | 描述 | 特点 |
|------|------|------|
| **固定尺寸策略** | 针对特定硬件平台或计算库，预设一组固定的分片尺寸 | 实现简单，但灵活性差，难以适应矩阵形状或任务变化 |
| **启发式规则策略** | 通过预定义规则动态决定分片方式（如最大化本地内存利用率、增加数据复用等） | 有一定提升，但依赖专家经验，难以应对多变环境 |

## 现有技术的不足

### 缺陷一：缺乏自适应与全局优化能力

**固定尺寸切分**采用预设分片尺寸，不随矩阵长宽比（M/N/K）、数据类型与精度、算子融合方式以及硬件资源（片上存储容量、带宽、计算阵列规模）变化而调整；本质上不进行搜索与优化，易导致片上存储利用不足、片外带宽占用或访存次数偏高、计算阵列利用率下降。
**启发式规则**往往以局部指标为依据逐步调整分片（具有贪心特征），缺乏全局视野与对后续影响的统筹，容易在不同矩阵形状、数据类型与硬件参数变化下收敛到局部最优，难以稳定得到全局最优解。

### 缺陷二：多重约束与优化目标强耦合，难以协调

M/N/K 三维分片尺寸、片上存储占用与复用策略、片外通信带宽、计算阵列利用率、数据预取与流水线调度等多个维度的约束与目标高度耦合。仅通过局部规则进行调整，容易导致内存溢出、带宽瓶颈或计算资源闲置等问题，无法在整体层面实现资源协同与性能最优。

### 缺陷三：可移植性与适应性不足

现有启发式规则多基于特定硬件架构（如固定内存容量、带宽与算力比例）和特定计算场景（如固定矩阵形状与数据类型）的人工经验设计，缺乏通用性。一旦硬件平台更新或计算任务发生变化，原有策略往往失效，需投入大量人力重新编写规则或调整参数。

## 核心创新

本发明的核心创新点包括：

### 创新点一：基于任务规模的场景识别与分流机制

提出一种基于输入矩阵 M/N/K 维度数据和硬件参数的快速场景分类方法。利用硬件参数与矩阵规模快速估算矩阵乘操作中通信与计算时间比 ρ = T_comm / T_comp，并据此将矩阵乘计算的整体耗时瓶颈问题划分为三种场景，触发不同的优化路径：

| 场景类型 | 条件 | 优化策略 |
|----------|------|----------|
| **计算主导型** | ρ ≤ ρ_low | 采用计算饱和模板（优先填满计算阵列、对齐维度、深化K方向复用） |
| **通信主导型** | ρ ≥ ρ_high | 采用带宽饱和模板（优先增大可复用维度切片、减少片外搬运次数、确保双缓冲覆盖） |
| **平衡型** | ρ_low < ρ < ρ_high | 进入图优化引擎进行联合优化 |

该机制能够在未知具体分片方案的情况下快速实现场景分流，以最小的决策成本实现系统效率最大化。

### 创新点二：面向平衡型场景的图模型与统一代价方案

针对计算与通信开销相当的平衡型场景，提出基于图搜索的系统化分片策略：

1. **解空间图建模**：将每个可能的切分方案用节点表示，节点沿 XYZ 三维坐标轴排布（分别对应 M/K/N 维度），节点之间使用双向箭头相连，用于表示对分片参数的调整动作（如 ±ΔM/±ΔK/±ΔN），整体构成一个立方体形状的搜索空间。
2. **统一代价评估模型**：融合计算、通信与内存约束惩罚的统一代价评估函数，引入可配置的权重系数，依据硬件特性动态调节代价计算倾向。
3. **导向性搜索机制**：采用 A* 搜索算法，在扩展节点时同步考虑历史路径代价与目标启发代价，通过实时内存约束检查实现剪枝操作，消除无效分支。

### 创新点三：基于硬件参数的动态权重调优机制

为实现跨硬件平台的高效适配，提出硬件特征库与在线校准相结合的权重调优系统。通过硬件参数初始化代价函数中的权重系数，并在实际部署后借助轻量级基准测试实现动态更新。

## 算法详解

### 1. 场景识别与分流

基于屋顶线模型（Roofline Model），分别估算通信耗时 T_comm 与计算耗时 T_comp：

- **T_comm 的估算**：以片外存储的理论带宽峰值为性能上限进行估算，得到耗时下界
- **T_comp 的估算**：以计算阵列的理论计算峰值为性能上限进行估算，得到耗时下界

通信与计算耗时比的计算公式为：

ρ = T_comm / T_comp


设定可在线校准的阈值区间 [ρ_low, ρ_high]（初始值可设为 [0.2, 5.0]）：

- 若 ρ ≤ ρ_low → **计算主导型**，采用计算饱和模板
- 若 ρ ≥ ρ_high → **通信主导型**，采用带宽饱和模板
- 若 ρ ∈ (ρ_low, ρ_high) → **平衡型**，进入图优化引擎

系统部署后可通过少量样本对阈值进行校准，使其更贴合实际硬件与工作负载。

### 2. 图模型建模

将三维矩阵分片问题建模为图搜索问题，图模型中包含以下元素：

**节点（State）**：表示一个分片方案，包含：
- 左矩阵行分片尺寸 M_slice
- 左矩阵列/右矩阵行分片尺寸 K_slice
- 右矩阵列分片尺寸 N_slice
- 预估通信耗时 T_comm
- 预估计算耗时 T_comp
- 内存使用状态 Mem_usage

**边（Action）**：表示对当前分片状态的调整，按 M/N/K 三维度的方向和步长进行调整，增加或减少切片尺寸。

**合法性检查**：在生成相邻节点前进行约束检查，非法节点将通过惩罚项直接舍弃。

### 3. 统一代价模型

**节点统一代价函数**：

f(n) = max(α · T_comp(n), β · T_comm(n)) + γ · Penalty(n)


其中：
- α 和 β 分别是预估计算耗时项和预估通信耗时项的系数，可随硬件参数改变
- 惩罚项 Penalty(n) 的系数 γ 在节点内存状态 Mem_usage 违反硬约束时启用

**路径累积代价**：

g(n) = f(s) + Σ C(e)


其中边代价为：

C(e) = max(α · ΔT_comp, β · ΔT_comm) + γ · Penalty(e)


- ΔT_comp：分片尺寸调整导致的计算耗时变化量
- ΔT_comm：分片尺寸调整导致的通信耗时变化量
- Penalty(e)：动作导致的约束违规惩罚

**启发函数 h(n)**：提供从节点 n 到目标节点的乐观代价下界，基于屋顶线模型的理论最优值：

h(n) = max(α · T_comp(n), β · T_comm(n))


确保 A* 算法可收敛（不高估实际代价）。

**任务感知的权重调整**：
- 对 FP32/FP16 任务，增大 α，目标为提升计算单元利用率
- 对 INT8/稀疏任务，增大 β，目标为减少片外搬运

### 4. A* 搜索算法

A* 算法通过代价函数指导节点扩展：

A(n) = g(n) + h(n)


其中：
- **g(n)**：路径累积代价，表示从起点到节点 n 的实际累积开销
- **h(n)**：启发函数，提供从节点到目标节点的乐观估计代价，需满足可容性（即不高估实际代价）

搜索过程中，每一步节点扩展都会即时进行严格的约束检查（如输出矩阵、左矩阵、右矩阵的存储空间是否足够），任何违反约束的方案会被赋予极高的代价并被排除，确保搜索路径始终在可行解空间内进行。

### 5. 硬件权重校准

**硬件特征库**包含以下信息：
- 存储层级：本地内存容量、数据搬运带宽、访问延迟
- 计算单元：数据维度、指令吞吐、对齐要求
- 运行时可用度：预留空间、其他任务干扰系数

**参数获取方式**：
- **离线标定**：通过微基准测试和硬件规格建立"硬件特征映射表"
- **在线校准**：部署时运行少量微基准测试，更新实际带宽和延迟，调整权重

## 有益效果

### 1. 实现分片方案的全局近似最优，显著提升整体性能

本方法能够系统性地在广阔的解空间中进行搜索，摆脱了传统启发式规则"贪心"决策导致的局部最优困境。通过构建以分片参数为状态节点、以参数调整操作为边的图模型，并采用 A* 搜索算法进行路径探索，其评估函数综合考量了计算耗时、通信开销与内存占用等多维度代价，确保最终输出的方案在满足所有约束的前提下总执行代价最小。

### 2. 高效处理多重耦合约束，提升系统稳定性和资源利用率

本方法能够高效处理 M/N/K 三维分片尺寸、片上存储、带宽、计算单元利用率等多重紧耦合约束。在图搜索的每一步节点扩展中都会即时进行严格的约束检查，任何违反约束的方案会被赋予极高的代价并被排除，确保搜索路径始终在可行解空间内进行，避免内存溢出、带宽瓶颈或算力闲置等问题。

### 3. 对不同硬件平台与不同任务场景的自适应能力，大幅降低部署成本

图的代价模型中的权重系数（α, β, γ）可根据目标硬件的具体特性进行配置。同时，图搜索本身不依赖于任何针对特定形状或硬件的预设规则，其优化目标（代价最小化）和约束条件（内存不超限）是通用化的。同一套系统只需输入不同的硬件参数和矩阵尺寸，即可自动生成相应的最优分片方案，无需为每个新平台或新任务重新设计规则或手动调参。
